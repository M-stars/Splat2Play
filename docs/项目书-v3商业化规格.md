### 2.2 技术方案与二进制格式规格

#### （1）为什么采用 `ScriptableObject (.asset)` + 二进制流文件 `(.s2pbin)` 双文件架构？
Unity 的 `ScriptableObject` 若直接序列化上百兆的 `uint[]` 数组，在 Inspector 选中该资产或触发 `AssetDatabase.SaveAssets()` 时会导致主线程严重卡死，且 YAML 文本膨胀数倍。因此商业级插件标准做法是：
- **`{Name}_SplatAsset.asset` (`GaussianSplatPrecompiledAsset`)**：仅存储轻量元数据（点数、SH 阶数、局部包围盒 `localBounds`、`ChunkBounds[]`、`ChunkSplatCounts[]`、`CameraInfo[]`、相对载荷路径 `PayloadRelativePath` 及 `PayloadCrc32`）。
- **`{Name}.s2pbin`（存放于 `Assets/StreamingAssets/scans/compiled/` 或同级目录）**：按 16 字节对齐连续存储 GPU 所需的四路原始字节流，运行时直接通过 `FileStream` 一次性读入 `NativeArray<uint>` 并调用 `GraphicsBuffer.SetData`，全程 **0 托管堆大数组分配、0 解码、0 排序**。

#### （2）`.s2pbin` 二进制文件头与内存布局（Little-Endian，64 字节固定头部）
文件位置：`Assets/Splat2Play/ThirdParty/GaussianSplatting/Runtime/GaussianSplatPrecompiledAsset.cs`

```csharp
using System;
using System.IO;
using System.Runtime.InteropServices;
using Unity.Collections;
using Unity.Collections.LowLevel.Unsafe;
using UnityEngine;

namespace GaussianSplatting.Runtime
{
    [StructLayout(LayoutKind.Sequential, Pack = 4)]
    public struct S2PBinHeader
    {
        public const uint kMagic = 0x42503253u; // "S2PB" (Little-Endian)
        public const uint kVersion = 1u;

        public uint Magic;              // 0x42503253 ("S2PB")
        public uint Version;            // 1
        public int SplatCount;          // 高斯点总数 N
        public int ShDegree;            // 0..3
        public int ShCoefficients;      // 0, 3, 8, 15
        public int MortonReordered;     // 1 = 已完成 30-bit Morton 空间重排, 0 = 原始顺序
        public uint PosBytes;           // N * 12 bytes (3 uints per splat)
        public uint OtherBytes;         // N * 8 bytes  (2 uints per splat)
        public uint ColorBytes;         // N * 4 bytes  (1 uint per splat)
        public uint ShBytes;            // N * ShCoefficients * 2 * 4 bytes (或 4 bytes 占位)
        public uint PayloadCrc32;       // 紧随 Header 之后的全部载荷字节的 IEEE 802.3 CRC32
        public uint Reserved0;
        public uint Reserved1;
        public uint Reserved2;
        public uint Reserved3;
        public uint Reserved4;          // 凑齐 16 * 4 = 64 字节头部
    }

    [CreateAssetMenu(menuName = "Splat2Play/Precompiled Splat Asset", fileName = "SplatPrecompiledAsset")]
    public sealed class GaussianSplatPrecompiledAsset : ScriptableObject
    {
        [Tooltip("相对于 StreamingAssets 的 .s2pbin 二进制载荷路径，或工程内相对路径")]
        public string PayloadPath;
        public int SplatCount;
        public int ShDegree;
        public int ShCoefficients;
        public bool IsMortonReordered = true;
        public Bounds LocalBounds;
        public uint PayloadCrc32;
        public Bounds[] ChunkBounds = Array.Empty<Bounds>();
        public int[] ChunkSplatCounts = Array.Empty<int>();
        public GaussianSplatCameras.CameraInfo[] Cameras = Array.Empty<GaussianSplatCameras.CameraInfo>();

        public string ResolvePayloadFullPath()
        {
            if (string.IsNullOrWhiteSpace(PayloadPath)) return string.Empty;
            if (Path.IsPathRooted(PayloadPath) && File.Exists(PayloadPath)) return PayloadPath;
            string p1 = Path.Combine(Application.streamingAssetsPath, PayloadPath);
            if (File.Exists(p1)) return p1;
            string root = Path.GetDirectoryName(Application.dataPath) ?? "";
            return Path.Combine(root, PayloadPath);
        }
    }
}
```

### 3.2 技术方案与数学模型

#### （1）为什么“Morton 序步进抽样（Strided In-Place LOD）”是零显存开销的最优解？
在 M6 中，所有 Splat 已经按 30-bit 3D Morton 码（Z-order 空间填充曲线）严格排序。Morton 序的核心数学性质是：**一维索引相邻的 $2^k$ 个点，在三维空间中严格聚集在同一个八叉树子立方体内**！
因此，在一个包含 $N_c \le 4096$ 个点的 Chunk 内：
- **LOD0（`flag = 1`，步进 $K = 1$）**：激活全部 $N_c$ 个 Splat；
- **LOD1（`flag = 2`，步进 $K = 4$）**：仅激活满足 `(localIdx & 3u) == 0u` 的 Splat，激活数量精确为：
  $$N_{\text{LOD1}}(N_c) = \left\lfloor \frac{N_c - 1}{4} \right\rfloor + 1 = (N_c + 3) \gg 2$$
- **LOD2（`flag = 3`，步进 $K = 16$）**：仅激活满足 `(localIdx & 15u) == 0u` 的 Splat，激活数量精确为：
  $$N_{\text{LOD2}}(N_c) = \left\lfloor \frac{N_c - 1}{16} \right\rfloor + 1 = (N_c + 15) \gg 4$$

> **关键不变量（Must Hold）**：  
> 在 `CSCullChunks` 中对 `_S2PIndirectArgs[1]` 执行 `InterlockedAdd` 的数量，**必须与 `CSCalcViewData` 中未早退（即写入 `< 0xFFFFFFFFu` 有效排序键）的 Splat 数量 100% 相等**！  
> 因为在 `GaussianSplatUtilities.compute` 中，`idx` 是当前渲染器内的全局索引（$0 \dots \text{SplatCount}-1$），而每个 Chunk 的大小固定为 $4096$（即 `kChunkSize = 4096`，且 $4096$ 是 $4$ 和 $16$ 的整数倍），所以 `idx & 3u` 与 `(idx - chunk.startSplatIdx) & 3u` **完全等价**！  
> 这意味着：
> - 在 `CSCullChunks` 中：
>   ```hlsl
>   uint activeCount = chunk.splatCount;
>   if (visible == 2u)      activeCount = (chunk.splatCount + 3u) >> 2;
>   else if (visible == 3u) activeCount = (chunk.splatCount + 15u) >> 4;
>   InterlockedAdd(_S2PIndirectArgs[1], activeCount);
>   ```
> - 在 `CSCalcViewData` 中：
>   ```hlsl
>   uint flag = _S2PChunkVisibleFlags[chunkIdx];
>   bool lodCulled = (flag == 0u)
>                 || (flag == 2u && ((idx & 3u) != 0u))
>                 || (flag == 3u && ((idx & 15u) != 0u));
>   if (lodCulled)
>   {
>       // 写入 NaN 与 0xFFFFFFFFu 排序键并 return
>   }
>   ```
> 两者激活的 Splat 数量在数学上**逐位严格恒等**！所有被 LOD 跳过的 Splat 均获得 `0xFFFFFFFFu` 排序键，经 Radix Sort 后全部排在绘制流末尾，被 `DrawProceduralIndirect` 的 `instanceCount` 一次性截断跳过！

#### （2）能量守恒尺度与不透明度补偿公式
当每 $K \in \{4, 16\}$ 个相邻高斯点仅保留 1 个代表点时，若不补偿尺度与不透明度，远景墙面会出现网状孔洞或变淡。设局部降采样步进为 $K$：
- **尺度补偿因子 $\gamma_{\text{scale}}(K)$**（使单个代表高斯的屏幕覆盖面积近似弥补被跳过的邻居）：
  $$\gamma_{\text{scale}}(K) = \begin{cases} 1.0, & K = 1 \text{ (LOD0)} \\ 1.65, & K = 4 \text{ (LOD1)} \\ 2.60, & K = 16 \text{ (LOD2)} \end{cases}$$
- **不透明度补偿因子 $\gamma_{\alpha}(K)$**：
  $$\alpha_{\text{comp}} = \min\left(1.0,\; \alpha \cdot \gamma_{\alpha}(K)\right), \quad \gamma_{\alpha}(K) = \begin{cases} 1.0, & K = 1 \\ 1.35, & K = 4 \\ 1.75, & K = 16 \end{cases}$$
- 在 `CSCalcViewData` 中，当 `_S2PLodScaleComp > 0` 时，将 `splatScale *= lerp(1.0, gammaScale, _S2PLodScaleComp)`，`opacityScale *= lerp(1.0, gammaAlpha, _S2PLodScaleComp)`。

#### （3）`CSCullChunks` 中的距离判定
在 `S2PGpuCulling.compute` 中新增 Uniform：
- `float4 _S2PCamWorldPos;`（`xyz` = 相机世界坐标，`w` = `_EnableChunkLod ? 1.0 : 0.0`）
- `float4 _S2PLodParams;`（`x` = `lod1Dist`，`y` = `lod2Dist`，均为局部空间或世界空间距离；推荐将相机世界坐标变换到渲染器局部空间 `_S2PCamLocalPos`，直接计算点到局部 AABB `[chunk.boundsMin, chunk.boundsMax]` 的欧氏距离：
  ```hlsl
  float3 closest = clamp(_S2PCamLocalPos.xyz, chunk.boundsMin, chunk.boundsMax);
  float dist = length(_S2PCamLocalPos.xyz - closest) * _S2PCamLocalPos.w; // w = transform.lossyScale 最大分量
  if (visible != 0u && _S2PLodParams.z > 0.5) // z = enableLod
  {
      if (dist >= _S2PLodParams.y)      visible = 3u; // LOD2 (1/16)
      else if (dist >= _S2PLodParams.x) visible = 2u; // LOD1 (1/4)
  }
  ```

### 4.2 技术方案与核心算法

#### （1）`ObbRange` 数学定义（Burst 兼容，`Assets/Splat2Play/Runtime/PlySplatReader.cs` 或 `ProxyTypes.cs`）
```csharp
public struct ObbRange
{
    public float3 Center;
    public float3 HalfExtents;
    public quaternion Rotation;      // OBB 局部 → 场景局部
    public quaternion InvRotation;   // 场景局部 → OBB 局部

    public static ObbRange FromBoundsAndEuler(Bounds localBounds, Vector3 eulerDeg)
    {
        quaternion q = quaternion.EulerXYZ(math.radians((float3)eulerDeg));
        return new ObbRange
        {
            Center = (float3)localBounds.center,
            HalfExtents = (float3)localBounds.extents,
            Rotation = q,
            InvRotation = math.conjugate(q)
        };
    }

    public bool Contains(float3 point)
    {
        float3 local = math.mul(InvRotation, point - Center);
        return math.all(math.abs(local) <= HalfExtents);
    }

    public float3 ToLocal(float3 worldPt) => math.mul(InvRotation, worldPt - Center);
    public float3 ToWorld(float3 localPt) => Center + math.mul(Rotation, localPt);
}
```
- **OBB 底面修补（Floor Inpainting in OBB Space）**：
  - 将背景点 $p$ 通过 `obb.ToLocal(p)` 转换到 OBB 局部坐标系；
  - 在 OBB 局部坐标系下，盒体恒为 $[-E_x, E_x] \times [-E_y, E_y] \times [-E_z, E_z]$，底面恒为 $y_{\text{local}} = -E_y$！
  - 直接复用现有的环形切片采样逻辑（$y_{\text{local}} \in [-E_y - 0.08, -E_y + 0.08]$，外扩 $0.20\text{ m}$ 环带），在局部底面铺设修补点 $p_{\text{local}} = (x_l, \bar{y}_l, z_l)$，最后通过 `obb.ToWorld(p_{\text{local}})` 与 `math.mul(obb.Rotation, new quaternion(0,0,0,1))` 变换回场景局部空间！
  - 当 `RotationEuler == Vector3.zero` 时，`ObbRange` 退化为恒等旋转，结果与 M8 原算法**逐位完全一致**！

#### （2）T11.4 3D 连通域 + 2D PCA 自动物件分割算法（`SplatAutoPropDetector.DetectProps`）
输入：`NativeArray<SplatRawX> splats`，参数：`AutoDetectOptions`（`GridResolution = 96`, `MinPropVolumeM3 = 0.015f`, `MaxPropVolumeM3 = 3.0f`, `MinSplatCount = 200`, `FloorClearance = 0.08f`, `CeilingHeight = 2.0f`）。
算法步骤（纯确定性 CPU/Burst，124 万点耗时 `< 120 ms`）：
1. **分位数包围盒与 $96^3$ 占用统计**：计算点云 $[2\%, 98\%]$ 分位包络，划分 $N = 96$ 网格，统计每格内 $\alpha \ge 0.2$ 的 Splat 数量 `cellCounts[idx]`。凡 `cellCounts[idx] >= 3` 的体素标记为实心（`occupied = 1`）。
2. **主地面高度 $y_{\text{floor}}$ 自动检测**：
   - 在下半区 $y \in [0, N/2)$ 内，统计每一水平层 $y$ 的实心体素总数 $H(y) = \sum_{x,z} \text{occupied}(x,y,z)$；
   - 取满足 $H(y) \ge 0.15 \cdot \max_k H(k)$ 的最低局部峰值层作为地面层 $y_{\text{floor}}$。
3. **候选区域掩码与外墙剥离**：
   - 仅保留位于高度区间 $[y_{\text{floor}} + \lceil 0.08 / \text{step} \rceil,\; y_{\text{floor}} + \lfloor 2.0 / \text{step} \rfloor]$ 内的实心体素；
   - 将触碰水平边界（$x \le 1$ 或 $x \ge N-2$ 或 $z \le 1$ 或 $z \ge N-2$）或单簇水平跨度超过场景宽度 $45\%$ 的体素连通分量判定为“结构墙壁/大背景”并剔除。
4. **3D 6-邻域 BFS 连通分量标记（CCL）**：
   - 按固定线性索引顺序 $0 \dots N^3-1$ 扫描剩余实心体素，使用队列执行 6-邻域 BFS，得到若干独立连通簇 $C_1, C_2, \dots, C_m$。
5. **XZ 平面 2D PCA 主轴方向与 OBB 拟合**：
   - 对每个满足体积与点数约束的簇 $C_k$，计算其所有体素中心在水平面 $(x, z)$ 的 $2 \times 2$ 协方差矩阵：
     $$\Sigma_{xx} = \frac{1}{|C_k|}\sum (x_i - \bar{x})^2, \quad \Sigma_{zz} = \frac{1}{|C_k|}\sum (z_i - \bar{z})^2, \quad \Sigma_{xz} = \frac{1}{|C_k|}\sum (x_i - \bar{x})(z_i - \bar{z})$$
   - 主轴偏航角（Yaw）：
     $$\theta_y = \frac{1}{2} \operatorname{atan2}\left(2\Sigma_{xz},\; \Sigma_{xx} - \Sigma_{zz}\right)$$
   - 将簇内点旋转 $-\theta_y$ 后求紧致 min/max（外扩半个体素步长），即可构造带精确旋转角 `RotationEuler = (0, deg(θ_y), 0)` 的 `DynamicPropVolume`！

#### （3）T11.5 凹体多凸包组合碰撞生成（`SplatCompoundColliderBuilder`）
针对凹形物体（如桌子四条腿之间有空腔、L 型拐角沙发），单一 `MeshCollider(convex=true)` 会把空腔封死。
- 新增枚举 `public enum PropColliderMode { SingleConvexHull = 0, CompoundBoxes = 1 }`。
- `SplatCompoundColliderBuilder.BuildBoxes(NativeArray<SplatRawX> propSplats, int maxBoxes = 8, int gridRes = 12)`：
  1. 在局部点云包围盒上划分 $12 \times 12 \times 12$ 占用体素网格；
  2. 执行 **贪心三维长方体合并（Greedy 3D Box Merging）**：每次从第一个未访问的实心体素出发，沿 $+X, +Y, +Z$ 扩展出最大的全实心长方体并标记已消费；
  3. 若长方体总数超过 `maxBoxes`（默认 8），按体积从大到小保留前 `maxBoxes - 1` 个主长方体，并将剩余零散实心体素合并为第 `maxBoxes` 个包络盒（或将距离最近的相邻盒合并），输出 `List<Bounds>` 并在动态物体 GameObject 下直接挂载对应数量的 `BoxCollider`！

### 5.2 技术方案与分类准则

#### （1）高斯色度 + 几何扁平度多模态分类准则（`S2PSurfaceClassifier.ClassifySplat`）
对于每个 Splat，由直流球谐分量 `Fdc` 还原线性颜色 $c = \operatorname{saturate}(0.5 + 0.28209479 \cdot \text{Fdc})$，并调用 `SplatNormalMath.ExtractNormalAndFlatness` 计算扁平度 $w_{\text{flat}} \in [0, 1]$。设 $M = \max(R, G, B)$，$m = \min(R, G, B)$，饱和度 $S = (M - m) / \max(M, 10^{-4})$：
1. **FoliageOrCarpet（植被 / 草地 / 软质地毯，`byte = 4`）**：
   - 绿色显著占优（$G > 1.15 \max(R, B)$ 且 $G > 0.12$），或高饱和度且低扁平度散射体（$S > 0.35$ 且 $w_{\text{flat}} < 0.22$）。
2. **Wood（木材 / 地板 / 木制家具，`byte = 2`）**：
   - 暖棕色/木色区间：$R > G > B$，且 $S \in [0.22, 0.80]$，$M \in [0.12, 0.78]$，$w_{\text{flat}} \ge 0.22$。
3. **Metal（金属 / 镜面硬质表面，`byte = 3`）**：
   - 极高明度低饱和度且极高扁平度：$S < 0.15$，$M > 0.68$，$w_{\text{flat}} \ge 0.65$。
4. **StoneOrConcrete（石材 / 混凝土 / 砖墙，`byte = 1`）**：
   - 中性低饱和度硬表面：$S < 0.22$，$w_{\text{flat}} \ge 0.25$（且未命中 Metal）。
5. **Default（默认，`byte = 0`）**：其余情况。

在 $32^3$ 材质网格的每个非空单元中，对落入该单元的 Splat 按不透明度加权投票，票数最高的非 Default 类别即为该体素的表面材质；并对空体素执行 1 步 6-邻域膨胀（使碰撞网格表面顶点落入紧邻体素时也能 100% 查到材质）。

### 6.2 技术方案与深度合成原理

#### （1）`SortedBlended` 模式下如何无冲突地获取前景深度？
在 `GaussianSplats.shader` 中：
- 颜色目标 `SV_Target0` 使用 `Blend OneMinusDstAlpha One`（Front-to-Back Under 混合，因为 Splat 按 Near → Far 升序绘制）。
- 如果绑定 `SV_Target1`（`_GaussianSplatDepthRT`，初始 Clear 为 `0.0`，即 Reversed-Z 最远平面）：
  - 注意 D3D12 中如果未开启独立 MRT Blend，所有 RenderTarget 共享相同的 `Blend OneMinusDstAlpha One`！
  - 在 `Blend OneMinusDstAlpha One` 下，每个片段对 `SV_Target0.a` 的贡献权重恰好是 $w_i = (1 - \alpha_{\text{dst}}) \cdot \alpha_i$，且最终累积不透明度为 $A = \sum_i w_i \in [0, 1]$！
  - 因此，如果在 `frag` 中将 `res.depth` 输出为 **`i.vertex.z * alpha`**（即预乘 $\alpha_i$ 的 Reversed-Z 深度 $z_i \cdot \alpha_i$）：
    - 经过硬件 `Blend OneMinusDstAlpha One` 后，`_GaussianSplatDepthRT.r` 中累积的值恰好是：
      $$D_{\text{accum}} = \sum_i w_i \cdot z_i$$
    - 而在 `GaussianComposite.shader` 中，只需要用累积深度除以累积不透明度 `col.a`：
      $$z_{\text{effective}} = \frac{D_{\text{accum}}}{\max(\text{col.a}, 10^{-4})}$$
      就能得到**数学上严格精确的、按可见透射率加权的期望表面深度（Expected Transmittance-Weighted Surface Depth）**！
    - **这一数学性质极其优美**：
      1. 完全不需要开启复杂的 Per-RenderTarget Independent Blend；
      2. 在 `Stochastic` 模式下（`SrcBlend = One, DstBlend = Zero, ZWrite = On`），$w_1 = 1, \alpha = 1, \text{col.a} = 1$，$z_{\text{effective}} = D_{\text{accum}} / 1 = z_1$，与原 `Reprojected` 模式下的 `res.depth = i.vertex.z` **100% 兼容且公式完全统一**！
      3. 在 `SortedBlended` 模式下，直接消除了传统 3DGS 无法输出平滑深度图的顽疾，且使 M3/M7 的 `SampleS2PDepth` 屏幕空间深度差分法线在 `SortedBlended` 模式下无需依赖代理碰撞网格即可直接对全体高斯点生效！
